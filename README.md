# peace-humanize

peace-humanize는 한글 글을 사람이 쓴 것처럼 새로 쓰거나 AI가 쓴 초안을 고치는 Claude 스킬입니다. 설치해 두면 카드뉴스나 블로그 글을 요청할 때 Claude가 처음부터 이 스킬의 규칙에 맞춰 씁니다. 이미 있는 글을 붙여 넣으면 내용과 숫자는 그대로 둔 채 문체만 고칩니다.

아래는 이 스킬로 숏폼에 대해 쓴 예시입니다.

> 숏폼은 결론이나 가장 궁금한 장면으로 시작하는 게 좋습니다. 인사나 채널 로고로 열면 본론이 나오기도 전에 다음 영상으로 넘어가 버리거든요.

## 설치

```bash
npx skills add peacemaintenancemaster/peace-humanize
```

위 명령은 Claude Code와 Codex와 Cursor에서 쓰는 설치 방법입니다. 이 명령이 통하지 않는 claude.ai 채팅에서 쓰려면 저장소의 `skills/peace-humanize` 폴더를 zip 파일로 묶어 설정의 스킬 메뉴에 올리면 됩니다.

## 사용법

글의 주제와 넣을 내용을 주면서 "카드뉴스 문구 써줘"처럼 요청하면 새 글을 씁니다. 그 글로 하려는 말이 정해지지 않았으면 스킬이 쓰기 전에 먼저 묻는 방식입니다. 이미 쓴 글을 붙여 넣고 "AI 티 없애줘"라고 하면 문체를 고치고 "이 글 AI 같아?"라고 물으면 고치지 않은 채 점검 결과만 보여 줍니다.

작업 전에 스킬이 묻는 것은 말투를 얼마나 편하게 할지 정하는 0에서 100 사이 값입니다. 이 값의 세 구간은 모두 존댓말이고 25나 75 같은 중간 값도 고를 수 있습니다.

- 0: 공지나 보도자료처럼 단정한 문체("~했습니다", "~입니다")
- 50: 블로그나 카드뉴스 문체("~습니다"와 "~어요"를 섞음)
- 100: 인스타그램 캡션처럼 편한 문체("~거든요", "~잖아요")

"~했다"로 끝나는 칼럼처럼 존댓말이 아닌 글은 "원문 톤 유지"를 고르면 문체를 그대로 둔 채 AI 흔적만 지웁니다.

## 규칙의 출처

규칙은 사람이 만든 카드뉴스 120세트와 AI 비중이 높은 블로그 글 120세트를 비교해서 둘을 실제로 구분하는 항목만 모은 것입니다. 예를 들어 사람 글에서는 쉼표가 들어간 문장이 열 개 중 세 개를 넘지 않았는데 ACL 2025에 실린 한국어 AI 글 연구(KatFish)에서도 사람 글 26%와 AI 글 61%로 같은 방향의 차이가 나왔습니다. 이 밖에 번역투와 AI식 관용구를 잡는 규칙은 [im-not-ai](https://github.com/epoko77-ai/im-not-ai)에서 가져왔고 전체 규칙은 `skills/peace-humanize/references/house-rules.md`에 있습니다.

## 측정 스크립트

스킬이 결과 검사에 쓰는 측정 스크립트는 파이썬만 있으면 따로 실행할 수 있는 도구입니다.

```bash
python skills/peace-humanize/scripts/house_check.py 고친글.txt --base 원문.txt --level 0
```

스크립트는 AI 글에 자주 나오는 단어와 쉼표 비율 같은 항목마다 PASS 또는 FAIL을 표시하고 `--base`로 원문을 주면 원문의 숫자가 빠졌는지도 검사합니다.

## 한계

스크립트는 문장의 겉모양만 보기 때문에 하려는 말이 분명한지나 문장끼리 이어지는지는 거의 판단하지 못합니다. 스크립트를 통과한 글도 사람이 한 번은 읽어 봐야 합니다. 스크립트가 잘못 판정한 사례를 발견하면 이 저장소의 이슈로 알려 주십시오.
