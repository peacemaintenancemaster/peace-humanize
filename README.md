# peace-humanize

ChatGPT나 Claude로 쓴 초안에는 공통된 흔적이 남기 마련입니다. 문장마다 쉼표가 찍히고 "다만"으로 시작하는 문장이 반복됩니다. 어미도 처음부터 끝까지 한 가지입니다. 저희 팀은 카드뉴스와 블로그 글을 고칠 때마다 이 흔적을 손으로 지워 왔습니다. peace-humanize는 그 작업을 Claude 스킬로 옮긴 것입니다.

고치기 전과 후는 다음과 같습니다.

> 숏폼은 단순히 짧은 영상이 아니라, 브랜드와 고객을 잇는 핵심 채널이에요. 결론적으로 숏폼은 마케팅의 새로운 패러다임이라고 할 수 있어요.

> 숏폼은 짧은 영상으로 끝나지 않습니다. 브랜드가 고객을 만나는 통로가 되었습니다.

바꾸는 대상은 말투뿐입니다. 내용과 숫자와 고유명사는 원문 그대로 둡니다.

## 규칙의 출처

이 규칙은 비교에서 나왔습니다. 저희는 사람이 만든 카드뉴스 120세트와 AI 비중이 높은 블로그 글 120세트를 나란히 놓고 분석했습니다. 그 가운데 두 집단을 실제로 구분하는 항목만 남겼습니다.

쉼표가 대표 사례입니다. 사람 글에서 쉼표가 들어간 문장은 열 개 중 세 개를 넘지 않았습니다. ACL 2025에 실린 한국어 AI 글 연구(KatFish)의 결과도 비슷합니다. 사람 글은 26%, AI 글은 61%였습니다.

번역투와 AI식 관용구를 잡는 규칙은 [im-not-ai](https://github.com/epoko77-ai/im-not-ai)에서 가져왔습니다. 두 규칙이 충돌하면 카드뉴스 비교에서 나온 규칙을 따릅니다.

## 설치

```bash
npx skills add peacemaintenancemaster/peace-humanize
```

지원 대상은 Claude Code와 Codex와 Cursor입니다. 직접 설치하려면 저장소를 내려받은 뒤 `skills/peace-humanize` 폴더를 `~/.claude/skills/` 아래에 두면 됩니다. 특정 프로젝트에서만 쓰려면 해당 프로젝트의 `.claude/skills/`에 넣으십시오.

claude.ai 채팅에서는 같은 폴더를 zip 파일로 묶어 설정의 스킬 메뉴에 올리면 됩니다.

## 사용법

글을 붙여 넣고 "AI 티 없애줘"라고 요청하면 윤문을 시작합니다. "이 글 AI 같아?"라고 물으면 글을 고치지 않고 점검 결과만 보여 줍니다. 재료를 주고 카드뉴스 문구를 요청하면 새 글을 씁니다.

스킬은 작업 전에 구어체 정도를 묻습니다. 세 구간은 모두 존댓말입니다.

- 0: 보도자료와 공지에 맞는 단정한 문체. "~했습니다", "~입니다"
- 50: 블로그와 카드뉴스에 맞는 문체. "~습니다"와 "~어요"를 섞음
- 100: 인스타그램 캡션에 맞는 편한 문체. "~거든요", "~잖아요"

해라체로 쓴 칼럼은 "원문 톤 유지"를 고르면 됩니다. 이 경우 스킬은 문체를 바꾸지 않고 AI 흔적만 지웁니다. 25나 75 같은 중간 값도 가능합니다.

## 측정 스크립트

윤문 결과의 검사는 측정 스크립트가 맡습니다. 필요한 것은 파이썬 하나입니다.

```bash
python skills/peace-humanize/scripts/house_check.py 고친글.txt --base 원문.txt --level 0
```

스크립트는 금지어와 쉼표 비율 같은 항목마다 PASS 또는 FAIL을 표시합니다. `--base`로 원문을 지정하면 원문 숫자의 누락 여부도 검사 대상이 됩니다.

## 한계

이 스크립트는 형태소 분석기 없이 만든 도구입니다. 종결어미를 끝 글자로만 분류했기 때문에 판정이 틀릴 때가 있습니다. "지수" 같은 금지 이름도 문맥에 따라 잘못 잡힐 수 있습니다. 잘못된 결과를 발견하면 이슈로 알려 주십시오.

규칙을 바꾸려면 `skills/peace-humanize/references/house-rules.md`를 수정하면 됩니다. 스크립트 판정까지 맞추려면 `house_check.py` 상단의 단어 목록도 함께 고쳐야 합니다.
